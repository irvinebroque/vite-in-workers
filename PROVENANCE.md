# Source provenance

Reviewed on 2026-10-28. The publishable project contains its own application,
tests, build scripts, compatibility adapters, and a patch against official
Rolldown source. It includes no third-party proof-of-concept checkout, copied
shim package, prebuilt compiler, or patches to N-API/emnapi/WASI.

## Build inputs

- **Rolldown:** the official [1.2.15 source commit](https://github.com/rolldown/rolldown/tree/89d821ca07cf9ccd84dd92bd3f48af0f579ab21a).
  `toolchain/upstream.json` pins its identity. The build verifies the commit and
  uses its unchanged Cargo lockfile with `--locked`.
- **JavaScript API:** official `@rolldown/browser@1.2.15`. Preparation reads its
  generated binding export names and connects them to our loader. The package's
  prebuilt WASM and worker-thread loader are not used.
- **Vite:** official `vite@8.3.5`. The package is unmodified on disk; esbuild
  applies the documented local packaging substitutions to its Worker copy.
- **WASM bridge:** official `@emnapi/core` and `@emnapi/runtime` 2.0.0-alpha.5,
  `emnapi` 2.0.0-alpha.5, and `@tybys/wasm-util` 0.10.3. npm integrity hashes are
  in `package-lock.json`; no patched copies of these libraries are supplied.

## Adapter origins

| Project implementation | Official interface or source it targets |
| --- | --- |
| `toolchain/worker-runtime.rs` | N-API's public [`AsyncRuntime` interface](https://github.com/napi-rs/napi-rs/blob/8bab46ee5dfd48a7b51e8bad3d09aed315ada4df/crates/napi/src/tokio_runtime.rs), Tokio's current-thread runtime, Rust's [`poll_fn`](https://doc.rust-lang.org/std/future/fn.poll_fn.html) and `Waker::wake_by_ref` |
| `toolchain/rolldown.patch` | Official Rolldown binding initialization and `rolldown_plugin_utils/src/asset_emission.rs`; the WASM path uses `std::fs::read` over the in-memory filesystem |
| `compat/rolldown.ts` | emnapi's context/features and module-instantiation APIs, emnapi's async-work/TSFN plugins, WASI preopens, and the registration exports generated by N-API |
| `compat/fs*.cjs` | memfs's filesystem and promise APIs; Node's `realpath.native` aliases |
| `scripts/prepare.js` | esbuild resolve/load plugins and parser-based `define` substitutions; Vite's own embedded lexer, CommonJS imports, and serialized preload function |
| `src/`, editor, examples, tests | Project-specific request/build/storage/preview behavior using documented Vite, Cloudflare, React, and Playwright APIs |

The executor drives a self-waking root future for a fixed number of polls, then
returns to JavaScript. It does not use a keepalive task, private global runtime
hooks, vendor-library patches, or a downloaded third-party compiler binary.

## Review scope

The publication review compared the project source against the earlier reference
experiment, checked the compatibility adapters against official package source,
replaced the scheduler's earlier keepalive approach, and checked both lockfiles
and build inputs. No implementation from that reference repository is retained.
Earlier research did consult it; this is not a claim that development occurred
without exposure to prior work. Shared API names and standard language idioms
are expected. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) for upstream
source notices.

Raw reports, screenshots, private deployment metadata, credentials, build
outputs, and temporary audit checkouts are ignored by Git. `VALIDATION.md` holds
the public, deployment-independent summary.
