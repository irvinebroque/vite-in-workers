# Validation

Checked on **2026-10-28**. This is a tested proof of concept, not a claim of complete
Vite ecosystem compatibility or a production security audit.

Final local checks use Node 24.22.0, which satisfies the pinned cf CLI's engine
requirement. `.node-version` records that version.

Hosted validation uses a deployment selected through `BUILD_URL` and a private
`BUILD_TOKEN`. Deployment URLs, request IDs, raw reports, and screenshots remain
in the gitignored `reports/` directory. They are local validation artifacts, not
part of the published source. Deploy your own instance with `cf` as described
in [README.md](README.md).

## Reproducible checks

| Check | Command | Scope |
| --- | --- | --- |
| Clean dependency installation | `npm ci` and `npm ci --prefix host` | Both lockfiles |
| Upstream compiler build | `npm run build:rolldown` | Official release, locked Rust dependencies, local WASM compilation |
| Binary provenance | `npm run check:toolchain` | Matching source hashes, non-shared memory, no thread-creation imports |
| TypeScript | `npm run typecheck` | Strict Worker and adapter checking; bindings generated by `cf workers types` |
| Integration | `npm test` | Real local workerd and R2 persistence across restart |
| Browser | `npm run test:browser` | Chromium against `cf dev` |
| Hosted integration | `BUILD_URL=… BUILD_TOKEN=… node scripts/verify.js` | Same suite against the deployed endpoint, plus CPU-limit enforcement |
| Hosted browser | `BUILD_URL=… BUILD_TOKEN=… npm run test:browser` | Chromium against the deployed endpoint |
| Small library demo | `npm run demo` | Two modules exporting 42 |
| Backend demo | `npm run demo:backend` | Build then execute in a separate Dynamic Worker |
| Dependency advisories | `npm audit` in root and `host/` | Registry advisory scan; not a code audit |

Do not place a real token directly in shell history; set the environment through
your secret manager or read the private JSON file in a local script.

## Tested surface

- JavaScript and TypeScript modules, changing inputs created after packaging,
  tree shaking, missing imports, syntax errors, and source locations.
- React 19.3.1 TSX rendering and state updates; clsx and React's scheduler dependency.
- HTML entrypoints, ordinary CSS and CSS imports, JSON, SVG emission, source maps,
  and dynamic import chunks loaded successfully in Chromium.
- Edit → build → preview → edit → rebuild; a failed build preserves the last
  successful preview. Drafts survive page reloads and can be reset to the example.
- Saved source, immutable artifact URLs, authenticated deletion, and local R2
  persistence through a complete runtime restart.
- Simultaneous builds and no files carrying over into the next compiler isolate.
- Authentication, method/path handling, malformed JSON, request/file size limits,
  path traversal, missing packages, Node built-ins, remote JS imports, and imports
  outside the project.
- Browser sandbox enforcement: parent DOM/storage unavailable; fetch blocked;
  sandbox also applies to direct preview navigation.
- Generated backend executes in a separate Worker with only its explicit binding,
  no compiler globals, and no outbound network.
- Hosted backend CPU limits terminate a deliberately infinite loop and return
  a handled execution error. This check is skipped in local workerd.

Final result: **10 integration groups and 2 Chromium tests passed locally;
10 integration groups and 2 Chromium tests passed against the hosted deployment.**
Both root and host dependency audits reported zero known vulnerabilities. Raw
advisory results are saved as `reports/audit-root.json` and `reports/audit-host.json`.

Gitignored, machine-readable results are generated in `reports/local.json`, `reports/hosted.json`,
`reports/browser-local.json`, and `reports/browser-hosted.json`. The integration
reports contain the executed checks and per-request measurements. Browser reports
contain the test outcomes, and `reports/preview-*.png` capture the working editor.

## Upstream compiler build

The old third-party fork dependency is removed from both npm manifests. The
compiler now comes from official Rolldown **1.2.15**, commit
`89d821ca07cf9ccd84dd92bd3f48af0f579ab21a`, using Rust 1.99.0 and the upstream
Cargo lockfile. This matches Vite 8.3.5's declared `~1.2.14` range.

Two fresh source checkouts produced **identical WASM SHA-256 hashes** on this
machine; see `reports/rolldown-rebuild.json`. This is not a claim of reproducibility
across operating systems or architectures. `reports/rolldown-build.json` records
the source, recipe, patch, runtime, and binary hashes plus the actual WASM imports.
The binary uses non-shared memory and has no thread-creation imports. N-API's
thread-safe-function imports implement a JavaScript callback queue; they do not
create threads. The loader throws if a dependency tries to create a Worker.

Both integration suites assert the runtime's Vite and Rolldown versions, then
exercise builds from newly generated request data. The local tests ran again
after a clean `npm ci`. The two CLI demos also passed. No local Vite process or
external compilation service handles the submitted application builds.

## Measurements and their meaning

Each build uses a new compiler Worker. Repeated requests do **not** represent a
warm compiler session. Durations are measured by the test client and include
request transport, compiler startup, Vite, serialization, and R2 storage.

In the final hosted React run, the two requests took approximately **2.13–2.44 s**;
local React requests took approximately **0.38–0.40 s**. The slowest request in
that hosted run took **2.44 s**. Raw samples are in the JSON reports. These are small fixtures and small samples,
not latency percentiles, a regional comparison, or capacity benchmarks.

The React build used **90,243,072 bytes (~86 MiB)** of linear WASM memory; the tiny
JS build used **69,468,160 bytes (~66 MiB)**. This is memory observed after a build,
not peak memory or total isolate memory. Our loader starts at 64 MiB; the compiled
binary declares a minimum of 1001 pages (about 62.6 MiB).

The deployed host and modules total about **29.4 MiB uncompressed / 6.4 MiB gzip**.
`reports/toolchain.json` records exact module sizes and SHA-256 hashes. `cf deploy`
reported host startup at 2 ms; this excludes dynamic compiler initialization and
is not a Vite startup measurement. Hosted success establishes that this fixture
fits this account and deployment; it does not establish headroom for large apps.
`reports/deployment.json` identifies the tested deployed version.
Both hosted suites passed against that final deployment.

Earlier hosted runs, before the upstream Rolldown migration, encountered R2 `put` failures (`InternalError 10001`) while
saving the roughly 1.6 MB React revision, plus browser requests that stalled for
up to 90 seconds. An R2 error also occurred with the final `WorkerLoader.load()`
implementation before the successful final runs. The root cause remains
unresolved; neither the loader simplification nor explicit UTF-8 uploads should
be presented as a proven fix. Cloudflare's [error reference](https://developers.cloudflare.com/r2/api/error-codes/)
classifies 10001 as a service error and recommends retrying. Selected invocation
timings and request IDs are in `reports/hosted-observations.json`. Temporary
stage logging was removed from the final code.

Browser assertions allow 45 seconds, with a 120-second test limit, to accommodate
the compiler's 30-second CPU budget plus startup and transport. These are
functional checks, not a latency guarantee. Storage failures remain handled 503
responses; the demo does not silently retry them.

## Explicit limits

No dev server/HMR, incremental compiler cache, arbitrary npm installation, user
plugins/configuration, SSR framework, Tailwind, Sass, native minification, binary
image uploads, TypeScript type checking, load/soak testing, cross-browser testing,
or total-isolate/peak-memory measurement is claimed. CPU and memory behavior for
larger inputs remains uncharacterized. Builds use our threadless port of upstream
Rolldown 1.2.15 with Vite 8.3.5, as explained in [COMPATIBILITY.md](COMPATIBILITY.md).

The stable local Miniflare pin has two development-only dependency overrides:
Undici 7.30.1 and Sharp 0.35.5 fix registry advisories in its original dependency
versions. These are local test-tool dependencies; they are absent from the hosted
compiler. The host CLI package is independently pinned. Both dependency graphs
are checked separately.
